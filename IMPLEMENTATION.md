## Practical limits

- Music now uses one gain curve across Spotify/Navidrome and optional fixed normalization with automatic album/track selection. [The contract](docs/wiki/features/music.md#source-volume-and-normalization-2-october-2026) records the enabled-by-default setting, next-track timing, conservative attenuation and metadata assumptions. Real-account tag coverage and measured loudness parity remain separate validation limits.
- Scheduled Linkding refresh and exact-item/cross-module source navigation now close the earlier D41/D18/D85 implementation gaps. Linkding remains one-way, preserves local edits, does not mirror upstream deletions, and runs only while Clarity is open. Live-provider compatibility is still a separate check.
- Full GFM is the Notes compatibility requirement. The tested editing examples establish useful coverage, not exhaustive GFM conformance. Trash recovery is manual; filenames are retained, but the original folder is not recorded in a restore manifest.
- Real macOS location permission and device acquisition require the user's OS response and working Location Services. Fixtures cover granted/denied/unavailable outcomes; they do not establish successful real device positioning. Turning location off clears future context, not information already sent in prior requests or replies. Native device location is currently macOS-only; timezone and manual location also work elsewhere.
- Live Gmail, X and Linkding still need account/server validation. Navidrome direct authentication passes; normal installed recovery awaits macOS access, and real-server playback/formats remain unverified. Spotify's installed direct OAuth-token path passes real expired-access-token renewal, playback/seek/resume, and saved-connection reuse after Quit/reopen. Fresh browser OAuth, refresh-token expiry/revocation, listener-confirmed audibility, and other audio devices remain unverified. Fixtures establish our control flow, not compatibility with every live service.
- Existing Codex credentials work. Fresh ChatGPT OAuth is implemented but has not been exercised against a fresh live account; account-expiry behavior also remains a live validation item.
- Interactive browsing uses installed Chrome/Chromium. Exact-origin grants last for the thread. Consequential-action classification relies on the agent; it is not a universal read-only browser sandbox. Codex-level latency has not been established by comparative measurement.
- macOS arm64 is validated. Linux development remains possible but unverified; there is no Linux package or notarized public distribution.
- No external-agent board adapter, background service, launch-at-login, device sync, terminal module, or local-file music library.
