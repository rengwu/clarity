# 19 October 2026 — Pi Durable recovery and approvals

## Scope

**FEAT-chat experimental execution**, under [D133](../../decisions/index.md#d133-pi-durable-recovery-and-approval-spike-19-october-2026). The [experimental contract](../../foundations/harnesses.md#pi-durable-experiment-19-october-2026) requires explicit Resume after restart and automatic task continuation after Apply. Summaries are deferred. This report certifies the disposable prototype and selected service boundaries, not installed-app behavior or a production migration.

## Build and environment

macOS arm64, Node v22.19.0; unchanged Clarity source revision `713fa7d040fd208dbc5b7d639aa48714ee191ece`. The working tree contained the newly collected interview transcript; no application source changed. [Identity evidence](../../evidence/2026-10-19T072255Z-pi-durable/identity.json) records hashes of every bundled application input, the Worker, spike source/bundles and external lockfile, with after-run comparisons confirming unchanged application source. Pi Durable, Pi AI and Chord are pinned to 1.3.0 in the external spike; the baseline resolves the application's existing Pi 0.87.1 dependencies.

External source: `~/Library/Caches/Clarity/spikes/2026-10-19-pi-durable/`. Commands: `node build.mjs` then `node verify.mjs > verification.log 2>&1`. The [reproduction notes](../../evidence/2026-10-19T072255Z-pi-durable/reproduction.txt) explain the scripts, dependencies, fault injection and cleanup. The driver uses a fresh synthetic module data root and real workerd/SQLite per scenario; each agent child owns Node SQLite storage. SIGKILL interrupts the child at signalled cut points. Selected cases close/reopen the module store too. Named IPC commands exercise the prototype's real Resume/Stop/Close handlers, and Apply invokes real `Modules.approve`. There is no renderer in this experiment.

Both providers are controlled: the baseline replaces the stream function in real `Chats.makeAgent`; the candidate uses Pi's shipped faux provider. No real credential, connected account, user data, model API or external effect is used. Importing `Chats` requires a `nativeImage` stub; no Electron image/UI behavior is covered. Compaction is disabled. All owned processes, sockets and Worker instances are closed in fixture cleanup.

## Results

The [final log](../../evidence/2026-10-19T072255Z-pi-durable/verification.log) and [structured observations](../../evidence/2026-10-19T072255Z-pi-durable/observations.json) record **15 passed, zero failed**. Two passes are deliberately adverse controls that observed unsafe behavior when integration protections were omitted; they are not claims that those configurations satisfy the product contract.

D09's idempotence is a special fixture using a deterministic record ID through the real Store; it does not claim current `todos.add` supports idempotency keys. D11 reconstructs the crash window through the real service/store methods rather than killing Electron during Apply. The approval bridge serializes request creation and uses a task-specific owner to find an existing action after a crash before link persistence; this must be replaced with a production-compatible operation identity before adoption.

The first 14-scenario runtime run passed. A final run replaced the idempotent fixture's title lookup with a task-keyed ID and added D12 to check dependent tool execution. An earlier build-helper attempt needed ESM-aware dependency resolution; that setup error was corrected before runtime testing and is not a Pi Durable product failure. No independent review is claimed.

Documentation validation: [13 reader/report tests passed](../../evidence/2026-10-19T072255Z-pi-durable/wiki-tests.log); the report checker validated 31 reports, and the rebuilt 179-page wiki passed metadata, links, attachments and freshness checks. The [workspace fingerprint](../../evidence/2026-10-19T072255Z-pi-durable/project-fingerprint.json) captures the broader source inventory after the experiment; its cached-package fields describe an existing package, not a package tested here. Document checks do not certify runtime behavior.

## Limits and follow-up

This establishes recovery/approval control flow with scripted model outputs and real stored effects. It does not establish live model reasoning, semantic recovery, latency, maintenance savings or compatibility of the Codex subscription route on Pi 1.3.0. No live provider, fresh OAuth, renderer, packaged Electron, saved-chat migration, full mutation catalogue, browser grant, automatic approval catalogue, Cloudflare Pi storage adapter, concurrent writer or power-loss test was selected. Summaries are explicitly deferred, not a selected untested scenario.

Current app dependencies/source and installed bundle were not changed. Production integration remains a proposal. Its concrete prerequisites are per-conversation Resume control, stable operation IDs that preserve chat ownership, Close/Stop mapping, transcript/event migration, current Codex access, and native UI/package verification. Unsafe replay and shared-harness activation are demonstrated integration hazards, not unresolved fixture failures. [Technical assessment](../../references/technical-spikes.md#assessment-and-remaining-work) records the recommendation.
