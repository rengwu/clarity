# 1 October 2026 — UI and usability audit

The user requested an audit of bad UI, UX, usability issues, and inconsistencies, with a priority-sorted list. The [audit evidence register](../references/ui-audit.md) records nineteen findings, reproduction limits, source locations, and recommended remedies. The recommendations are not newly accepted requirements, and this work changes documentation only.

Built the current source into the existing external cache, then ran a separate Electron instance with a disposable data folder. Inspected all module screens, light and explicit dark themes, the normal and minimum window sizes, form submission/deletion, draft/navigation state, error presentation, and large lists. Mail/Music used controlled UI responses; playback used simulated events. No real account connection, model request, or audio playback was made.

The highest-priority observations concern lost drafts, unprotected permanent deletion, duplicate records from ordinary double-clicks, incomplete calendar/expense presentation, unreadable dark-mode Wiki text, stale calendar creation dates, unintended note moves during rename, and hidden automation action outcomes. Source review also confirms existing item-link and Linkding refresh limitations. Remaining findings concern feedback, approval readability, setup/navigation friction, attachment inspection, empty states, and unnamed dialogs.

Updated the affected current topics and follow-up list to link these findings without changing their accepted contracts. Kept both implementation summaries consistent. Screenshots, the disposable harness, and evidence remain under `~/Library/Caches/Clarity/build/ui-audit-2026-10-01/`. The isolated app was closed. The installed app, user data, source code, and existing uncommitted implementation changes were left untouched. Wiki generation and link/freshness checks pass after the documentation update. No application fix or new package validation is claimed.
