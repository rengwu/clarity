## Product changes

Chat/Expense drafts persist through navigation and reload; permanent record deletion asks for confirmation; forms reject overlapping submissions; local collection pages are fully loaded for visible appointments and complete expense totals. Wiki receives the chosen theme. Calendar creation follows the viewed period, and note Rename stays in the file's parent while retaining its tab. Action cards show readable changes and job-owned histories. Errors stay near their controls, Settings has section navigation, item links resolve actual records, and Wiki hands current-page context to the composer.

Board search reveals parents of matching replies. Mail retains page/message context with a one-page return; Music retains its collection stack while preserving the accepted Songs layout reset. Linkding reconciles upstream fields with per-field local-edit preservation and offers Manual/hourly/daily refresh while open. Attachment chips expose text/image inspection and retained-original reveal. Shared loading/empty states, primary hover colors and dialog names are consistent.

The existing feature topics own detailed behavior and failure paths. The [audit resolution register](../references/ui-audit.md#resolution-and-evidence) maps all fixes without erasing the original reproduction evidence.

## Limits

No new live account compatibility, VoiceOver walkthrough, exhaustive GFM proof, Linux build or clean-machine result is claimed. Mail/Music screens and Linkding use isolated controlled fixtures. Loading all local rows prioritizes correctness over a new large-data architecture; very large libraries can still cost memory/time. Unsent drafts use the existing local profile, and temporary Mail/Music view memory resets on renderer reload. The normal two-view Calendar, lean Expense scope, approval policy, and optional-module boundaries remain settled.
