# 25 September 2026 — Combined Music scope

The user wants one lean client combining Spotify and Navidrome if possible. Their final clarification includes both sources in all views, superseding the initial Navidrome-only Albums suggestion in the same message. Recorded [D47](../decisions/index.md#d47-combined-music-client-scope-25-september-2026).

Captured connection setup, player controls, list/grid collections, simple playlist/album detail, four search tabs, and recent collection items on Music Home. Artists appearing in both sources stay separate, every item identifies its source, and playlists never mix sources. Spotify-created playlists, Liked Songs, and nested playlist folders are requested. A combined search tab and source styling remain tentative. Screenshots are references only.

Official documentation confirms saved Spotify albums and tracks, but excludes playlist folders from the Web API. Spotify's Developer Policy also restricts combined-service content integrations; recorded this as a material concern rather than promising that separate playlists or an unofficial client resolves it. Sources and assessments are on the [Music page](../features/music.md#feasibility-findings-for-the-combined-scope).

Assistant proposals: source text badges/columns, a single active playback source, and Clarity-only recent context history. None is yet accepted. Remaining questions include folder feasibility, provider restrictions, history origin, source switching, library/search boundaries, and whether direct local files remain a third source. No account was connected and no application code was built.
